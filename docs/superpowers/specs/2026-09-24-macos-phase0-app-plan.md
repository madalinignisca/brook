Each task ends in a check; tests are written first and seen failing under their named mutation.

### M1 — Project skeleton, integrated with BrookCore
- `clients/macos/project.yml`: `packages.BrookCore.path: ../../bindings/apple/swift/BrookCore`;
  target `Brook` depends on package product `BrookCore`; `PRODUCT_BUNDLE_IDENTIFIER=dev.brook.Brook`,
  `MACOSX_DEPLOYMENT_TARGET=26.0`, `SWIFT_VERSION=6.0`, `ARCHS=arm64`, `CODE_SIGN_IDENTITY=-`,
  `ENABLE_HARDENED_RUNTIME=YES`. Plist and entitlements **generated by XcodeGen** from
  `info.properties` (`NSLocalNetworkUsageDescription`, `CFBundleDisplayName`) and
  `entitlements.properties` (`com.apple.security.app-sandbox: true`,
  `com.apple.security.network.client: true`) — never hand-edited (XcodeGen rewrites them).
- `clients/macos/build.sh`: runs `bindings/apple/build-xcframework.sh`, `xcodegen`, then
  `xcodebuild -project clients/macos/Brook.xcodeproj -scheme Brook -derivedDataPath clients/macos/build`
  (deterministic output path `clients/macos/build/Build/Products/Debug/Brook.app`). Always rebuilds the
  xcframework, so the app never links a stale `core`.
- `BrookTests/SmokeTests.swift` (hosted): constructs a real `FfiBrookClient` for `https://brook.invalid`
  and asserts `http://192.168.1.50` without the flag throws `InsecureServerUrl` — proves the app target
  links and calls the Rust core.
- **Check (on the built bundle, not the project):** `codesign -d --entitlements -` shows exactly the two
  keys; `codesign -dv` shows `flags=...runtime`; `plutil -p Contents/Info.plist` shows bundle id,
  `LSMinimumSystemVersion` 26.0 and the usage description; `lipo -archs` = `arm64`; smoke test green.

### M2 — `ServerAddress` + `Settings` (pure logic)
- `ServerAddress.parse(_:)`: trim, require scheme + host, reject userinfo/query/fragment.
  `Settings`: server prefill (env → defaults → `https://localhost`), insecure flag (env or default),
  last-good save — over injected `UserDefaults` + environment dictionary.
- **Check:** parser and resolution tests only (their *effect on the factory* is M3), each mutation-verified.

### M3 — `SessionStore` + `FakeClient`
- Store per spec §3.3 with injected factory; one `LoginError` → message function.
- `FakeClient: FfiBrookClient, @unchecked Sendable` via `init(noHandle:)`, overriding `login` and
  `subscribe`; call log + gate in a `Mutex` (`import Synchronization`), suspending **outside** `withLock`.
- **Check:** spec §5 rows about the store and factory — including "rejected address → factory never
  called, nothing saved" and "factory receives the resolved insecure flag" — each mutation-verified.

### M4 — Views + commands
- `LoginView` (`.textContentType(.URL/.username/.password)`, Return = default action, disabled + spinner,
  error text, insecure warning), `SignedInView`, single `Window`, standard commands.
- Password clearing lives in the view model the form binds to (`LoginForm`, `@Observable`): tested —
  cleared after success **and** failure (mutation: clear only on success).
- **Check:** tests green; then the app **launched from Finder** and driven for real (computer-use):
  Return submits; wrong password → message, field cleared, retry works; ⌘Q/⌘W/Edit menu (⌘A/⌘C/⌘V
  in a field); switch system appearance + accent → UI follows. Screenshots of each, light and dark.

### M5 — Docs + PR
- `docs/user-guide.md` macOS section; `clients/macos/README.md` build steps; `defaults delete
  dev.brook.Brook AllowInsecureHTTP` documented as cleanup.
- **Check:** draft PR opened.
